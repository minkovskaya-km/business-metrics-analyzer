# Ответы на контрольные вопросы

Практическое занятие №1. Настройка среды разработки и управление версиями.

## 1. Чем отличается Git от GitHub?

Git - это распределённая система контроля версий. Это программа, которая работает на компьютере и хранит историю изменений проекта. GitHub - это облачная платформа для хранения Git-репозиториев и совместной работы: на нём есть Pull Request, ревью кода и управление доступом. Git работает и без интернета, а GitHub нужен, чтобы делиться кодом с командой.

## 2. Для чего используется виртуальное окружение Python?

Виртуальное окружение создаёт для проекта изолированную среду со своими версиями библиотек. Зависимости разных проектов не конфликтуют друг с другом и не засоряют системный Python. Список нужных библиотек хранится в `requirements.txt`, и любой участник команды воссоздаёт такое же окружение командой `pip install -r requirements.txt`.

## 3. Что такое commit, branch, remote, pull request?

- **Commit** - фиксация изменений в истории проекта с описанием, что и зачем изменено.
- **Branch** - отдельная ветка разработки, в которой можно работать над задачей, не затрагивая основную ветку `main`.
- **Remote** - удалённый репозиторий (например, на GitHub), с которым синхронизируется локальный (`origin`).
- **Pull request** - запрос на слияние изменений из одной ветки в другую, в котором коллеги просматривают код, комментируют его и принимают.

## 4. Зачем нужен файл .gitignore?

В нём перечислены файлы и папки, которые Git не должен отслеживать и отправлять в репозиторий: виртуальное окружение (`.venv/`), кэш (`__pycache__/`), файлы с секретами (`.env`), настройки IDE (`.idea/`, `.vscode/`), временные и объёмные данные (`*.csv`, `*.xlsx`). Это держит репозиторий чистым и защищает от случайной публикации паролей и токенов.

## 5. Как организовать командную работу над бизнес-приложением с помощью Git?

Основная ветка `main` содержит рабочую версию. Каждый разработчик под новую задачу создаёт отдельную ветку, делает в ней коммиты и отправляет её на GitHub командой `push`. Затем создаётся Pull Request, коллега проверяет код и оставляет комментарии, и после одобрения ветка сливается в `main`. Перед началом работы участники делают `git pull`, чтобы получить свежую версию.

## 6. Какие файлы обязательно должны быть в репозитории учебного проекта?

- `README.md` (описание проекта и инструкция по запуску);
- `.gitignore`;
- `requirements.txt` (список зависимостей);
- исходный код (`main.py`);
- документация проекта (например, `docs/business_requirements.md`).

## 7. Что произойдёт, если два разработчика изменят один и тот же файл в разных ветках?

Если изменены разные части файла, Git объединит правки автоматически. Если изменены одни и те же строки, при слиянии возникнет конфликт: Git пометит спорные места маркерами. Конфликт нужно разрешить вручную: выбрать нужный вариант или объединить оба, затем выполнить `git add` и сделать коммит слияния.
